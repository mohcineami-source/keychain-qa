How it works

Both SDKs fire at every pixel loaded on the page and offer no way to un-load one, so changing either list reloads the page with a clean state — events only go to the IDs currently listed. Fire again re-fires at the current set without reloading.

One fire sends the same id to every pixel (one purchase, reported to several) as Snap's transaction_id and TikTok's event_id. Each fire gets a fresh id, so repeats log as distinct purchases instead of being deduped.

Query string

?snap= Snap IDs · ?tiktok= TikTok IDs · ?price= value · ?currency= ISO code · ?count= per pixel · ?auto=0 fill but don't fire on load
(?pixel= still works as an alias for ?snap=.)

A URL with ?snap= or ?tiktok= fires on load, so the link alone is a working test. Without them, the page just waits for the form. Last-used values are remembered in this browser.

Before you point ads at anything

Take this page down once the pixels are verified. While it's live, every visitor is reported as a completed purchase on whatever pixels are in the URL — that trains the optimizer on fake conversions and inflates the purchase count in Ads Manager. Only ever point it at pixels you own. It's a bench tool, not something to leave on a domain that receives traffic.
