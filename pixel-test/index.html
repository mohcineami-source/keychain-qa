How it works

Snap's library fires track at every pixel that has been init-ed on the page. To keep that predictable, changing the pixel list reloads the page with a clean state so events only go to the IDs currently listed — no leftovers from a previous set. Fire again re-fires at the current set without reloading.

Every fire gets a fresh transaction_id, so Snap logs each as a distinct purchase rather than deduping them into one.

Query string

?pixel= comma-separated IDs · ?price= value · ?currency= ISO code · ?count= purchases per pixel · ?auto=0 fill the form but don't fire on load

Loading with ?pixel=… fires on page load, so the URL alone is a working test. Without it, the page just waits for the form. Your last-used values are remembered in this browser.

Before you point ads at anything

Take this page down once the pixel is verified. While it's live, every visitor is reported to Snap as a completed purchase on whatever pixels are in the URL — that trains the optimizer on fake conversions and inflates the purchase count in Ads Manager. Only ever point it at a pixel you own. It's a bench tool, not something to leave on a domain that receives traffic.
